## 1. Who wrote the planted edits

The frozen records call the plantings "author-made" (PROTOCOL_PLANTINGS.md), say the mutants were "written by the author"
(docstring of scripts/planted_defects.py), and the reviewed paper said "we planted". The session records show who implemented
the study; the attribution of its design is the author's statement of 2026-09-29.

- The study design is the author's, with design options drafted with AI assistants at the author's request; an AI coding
  assistant (Claude Code) implemented it, and the author wrote none of the
  edits. A coordinating agent (Claude Fable 5.1) selected the eight base proofs, wrote the specification of the three edit
  kinds and their intended labels (fatal and gap: reject under both conventions; harmless: reject as written, accept repair-tolerant), and
  suggested candidate edits for each problem. Among its suggestions were the false monotone-quantity lemma of the P1 fatal
  edits (the Kimi-base edit uses it almost word for word; the GPT-base edit adapts it to a different quantity) and, word for
  word, the false finite-transversal lemma of the fatal edit on the public GPT-5.6-Sol pro P6 proof.
- Three Claude Fable 5.1 subagents, one per problem group, wrote every edit, every dependency argument, every intended label
  and all 16 executable checks (2026-09-06, 19:05 to 19:13 UTC). The coordinator wrote make_mutants.py and planted_checks.py,
  ran the checks, spot-checked four of the 24 diffs, launched the gates and made commit e5251501 (19:15:19 UTC), whose git author
  name comes from the configuration and which carries a Claude Fable 5.1 co-author trailer.
- The author decided the design (three edit kinds per proof, each published as a diff with a dependency argument and a
  check, the assistant doing the edits) before any edit existed, choosing to run it against the assistant's
  recommendation, and did not read or approve individual edits before the gates ran. The first examination by anyone other
  than the assistant was an internal model-run review that the author requested after the analysis freeze.
- The false lemma of both P1 fatal edits has the form of a natural error in a Nemotron P1 draft that the paper describes. The
  P1 closure rubric (closure_rubric_p1.txt), written earlier the same day by an AI subagent, gives that lemma as an
  example of a wrong approach scoring 0 on its mechanism fields; the P1/P5 planting subagent used it knowingly (plantings.json
  records "named in the rubric as a wrong approach").

"Author-made" is therefore corrected as follows: the study design is the author's, and the edits, their dependency
arguments, intended labels and checks, and the written specification are model-written under the author's direction.

## 2. What each gate's prompt contains

The reviewed version described the closure and witness gates as "separately prompted". They are prompted with the problem's
marking scheme, which the grade gate's prompt forbids. All figures below are read from the stored `runs/*/*/*/request.json`.

- Grade gate (`runs/grade/`, `runs/grade_rep2/`): the problem and the 0-7 coordinator scale. It says "Do not consult, recall, or
  compare against any published solution, and do not use a fixed list of required lemmas", and it does not define the
  `complete` field it asks for. System prompt length in characters, P1/P3/P5/P6: 2039/1957/1575/1807.
- Witness gate (`runs/witness/`): the problem's closure rubric (the marking scheme: "A complete proof needs ..."; the answer on
  P3 and P5; the value of M in P1's field mapping; example wrong approaches on P1, P5 and P6) with its return block replaced by
  the obligation-audit instructions, which include "Do not repair the argument for the author". Length 5692/4072/5519/4591.
- Closure gate (`runs/closure/`): the same marking scheme with the closure return block. Length 3365/1745/3192/2264.
- Reference checkers (`runs/refadj/`): the marking scheme and the statements of the reference ledger (LEDGER.md v1 of
  artifacts/reference_adjudication/).

Comparisons between the witness or closure gate and the rules read from the grade response (pass mark, strict mark, completeness
flag) are therefore reference-guided against reference-free, not information-matched. On P1 the scheme meets the planted edits
twice. (a) Both P1 fatal edits plant the false principle the P1 rubric names as a wrong approach (near-verbatim on the Kimi base,
reworded on the GPT base). (b) The P1 rubric requires the Euclidean step gcd(x, y - x) = gcd(x, y) with the x = y and
zero-valuation cases handled, and both P1 gap edits delete exactly that step. Four edits re-plant defects the paper describes in
natural proofs in the reviewed paper: the two P1 fatal edits (the Nemotron P1 lemma), the fatal edit on the public GPT-5.6-Sol pro P6 proof (the P6
finite-transversal lemma, which the reference ledger calls false), and the harmless edit on the P5 base (the (x+y+2C)/2 middle
term of the Nemotron P5 display, which the ledger pre-classifies as a harmless false line). The reference checkers saw the ledger;
the witness and closure gates saw the scheme; the grade gate saw neither.

Two further precisions. Each mutant is one search-and-replace edit of its original (plantings.json `search`/`replace`), but some
edits change more than one place in a line diff, so "single-hunk" is corrected to "single-edit". Every gap replacement contains
the words "(standard; details omitted)" and none of the other 24 texts does, so every deletion announces itself; unannounced
deletions were not tested.

## 3. What the executable checks establish

A check certifies that the planted statement is false (for a harmless edit, also that the next line continues from the correct
value); it does not show that a later line fails, and the dependency arguments are prose. The 8 gap edits have no check.

P5 release note (check_p5_gpt56_F in parts/checks_p1p5.py and the dependency argument of p5-gpt56-7324ef70-v1-F, both unchanged):
the check refutes the displayed expansion as an algebraic identity (lhs - planted = -8(b - c)(c + t)); no admissible instance
falsifies the displayed equality, since every solution has b = c; the planted error is an invalid step, and the quoted numeric
point (t = y = c = 1, b = 0, also in the dependency argument) lies outside the hypotheses, since the text defines c = d(t) and
b = d(y).
